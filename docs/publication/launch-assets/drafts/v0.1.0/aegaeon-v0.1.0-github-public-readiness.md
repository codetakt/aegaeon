> **Status note (2026-07-08):** Draft publication collateral; do not treat this as approved release wording, and check `docs/product-positioning.md` before reuse.

This checklist is for the public repository launch that accompanies the first press release.

## Repository front page

- README headline matches the current safe product statement
- README quick start has been smoke-tested
- README links to canonical docs that exist and are current
- badges are accurate
- screenshots or diagrams are ready if they are to be added

## Trust and governance files

- `LICENSE` present
- `SECURITY.md` present and current
- `CONTRIBUTING.md` present and current
- `CODE_OF_CONDUCT.md` present and current
- issue / PR templates reviewed

## Public release hygiene

- no private URLs, internal hostnames, or internal account names remain in docs
- no stale roadmap language implies unreleased SDK / client publication
- no documentation widens the current formal claim beyond the server boundary
- sample credentials / fixtures are test-only and clearly labeled

## Discoverability

- repository description updated
- GitHub topics added
- first public release tag / notes prepared
- website / documentation links added to repository settings

## Launch-day companion actions

- create release notes for `v0.1.0`
- pin the launch issue / discussion if needed
- verify all public links used by the press release and LP
- ensure the preview / PoC request URL is live

## Optional but valuable

- architecture diagram in README
- minimal deployment example
- short demo GIF or screenshots
- "Where to start" section for evaluators
